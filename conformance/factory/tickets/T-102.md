# T-102 — /health reports approvals summary

State: Ready
Branch: (planner creates: ticket/T-102-health-approvals-summary)
Risk class: low (read-only endpoint, no external actions)

## Description

T-101 gave operators queue counts on `GET /health`. The other thing an operator checks at a glance is the approvals pipeline: how many proposed actions are waiting for a human, and how the closed ones ended. Extend `GET /health` to also report approvals counts by status.

The approval statuses in `conformance/app/server.js` are: `pending`, `sent`, `rejected`, `blocked_recipient`. The existing `ok` and `queue` fields must not change (T-101's tests stay green).

## Acceptance criteria (planner freezes the exact contract)

1. On a fresh server, `/health` reports zero approvals in every status.
2. After a job completes and proposes an action, `/health` shows one pending approval.
3. After that approval is approved, `/health` shows it under sent, and pending returns to zero.

## Conventions

- App lives in `conformance/app/` (zero-dependency Node 18+; see `conformance/SPEC.md`).
- Tests go in `conformance/app/tests/` — new file `tests/health-approvals.test.js`, same style as the existing suites (node:test, spawn the real server on its own port with a temp DATA_DIR).
- Run tests from `conformance/app/` with `node --test tests/health-approvals.test.js`.
