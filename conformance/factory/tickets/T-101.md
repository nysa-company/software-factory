# T-101 — /health reports queue depth

State: In progress
Branch: ticket/T-101-health-queue-depth
Risk class: low (read-only endpoint, no external actions)

## Description

Operators need one glance to see whether Relay's job queue is healthy. Extend the existing `GET /health` endpoint to report how many jobs are pending, done, and dead.

## Frozen contract (v1)

`GET /health` returns HTTP 200 with JSON:

```json
{ "ok": true, "queue": { "pending": 0, "done": 0, "dead": 0 } }
```

- `ok` keeps its current meaning and stays `true` whenever the server responds.
- `queue.pending`, `queue.done`, `queue.dead` are integer counts of jobs in `state.jobs` by their `status` field.
- No other endpoint changes. No new endpoints.

## Acceptance criteria

1. On a fresh server (no events), `/health` returns `ok: true` and `queue: { pending: 0, done: 0, dead: 0 }`.
2. After an event is accepted and its job completes, `/health` reports `queue.done` incremented by 1.
3. After an event whose payload sets `failTimes: 99` exhausts retries, `/health` reports `queue.dead` incremented by 1.

## Conventions

- App lives in `conformance/app/` (zero-dependency Node 18+; see `conformance/SPEC.md`).
- Tests go in `conformance/app/tests/` — new file `tests/health.test.js`, same style as `conformance.test.js` (node:test, spawn the real server).
- Run tests from `conformance/app/` with `node --test tests/health.test.js`.
